# Руководство по участию в проекте OpenTS

Мы рады любому вкладу в развитие **OpenTS**! Будь то сообщение об ошибке, предложение новой функции, улучшение документации или пулл-реквест с кодом — любая помощь ценится.

---

## 🐛 Сообщение об ошибках (Bug Reports)

Если вы обнаружили баг:
1. Убедитесь, что используете последнюю версию приложения.
2. Проверьте [список открытых Issues](../../issues), возможно, проблема уже известна.
3. Если нет, создайте новый [Bug Report](../../issues/new?template=bug_report.md) и укажите:
   * Модель устройства и версию Android.
   * Шаги для воспроизведения проблемы.
   * Ожидаемое и фактическое поведение.
   * Скриншоты или логи (logcat), если применимо.

---

## 💡 Предложение новых идей (Feature Requests)

Хотите увидеть новую функцию в OpenTS?
* Создайте [Feature Request](../../issues/new?template=feature_request.md) с подробным описанием идеи и сценарием её использования.

---

## 💻 Разработка и Pull Requests

1. **Форкните репозиторий** и создайте новую ветку от `main`:
   ```bash
   git checkout -b feature/awesome-feature
   ```
2. **Требования к коду:**
   * Код на Kotlin должен следовать стандартным конвенциям Kotlin и Jetpack Compose.
   * Не нарушайте существующие комментарии и структуру JNI-моста с `tslib`.
   * Добавляйте строковые ресурсы в `res/values/strings.xml`, `res/values-ru/strings.xml` и `res/values-en/strings.xml`.
3. **Проверка сборки:**
   Перед отправкой PR убедитесь, что проект собирается без ошибок:
   ```bash
   ./gradlew assembleDebug
   ```
4. **Оформление PR:**
   * Опишите суть изменений в описании Pull Request.
   * Ссылайтесь на связанный Issue (например, `Fixes #12`).
